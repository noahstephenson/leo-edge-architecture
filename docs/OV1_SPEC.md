# OV-1 Specification

This describes what a concept graphic for the recommended allocation
should show. No image is generated by this document; the existing
`docs/figures/ov1_concept.png` predates this rework (it illustrates the old
onboard-vs-ground-processing framing) and should be treated as retired,
not representative of the allocation-space framing below, until a new
graphic is actually produced.

## What the graphic should depict

Two segments with a clearly drawn ownership boundary between them, not one
undifferentiated pipeline:

1. **Commercial LEO space segment** (provider-owned): the satellite,
   labeled with the tiered-product capability
   `docs/ACQUISITION_IMPLICATIONS.md` recommends requiring (at minimum a
   coarse/detection tier and an ROI tier, distinct from the full scene),
   and a direct-edge tasking interface alongside the reachback path.
2. **Army-owned tactical edge segment**: a terminal (either class from
   `docs/MISSION_THREADS.md`), receiving whichever tier(s) fit in a given
   contact window.
3. **Optional rear-echelon tasking cell**, drawn as a separate box
   connected to the edge terminal by the reachback tasking path, distinct
   from the direct-edge path that bypasses it.

## What the graphic should NOT show

- A single "satellite to ground" arrow with no tiering or ownership
  distinction (that was the old OV-1's framing, and is exactly what this
  rework moved away from, `docs/DECISION_LOG.md` ADR-007).
- Any specific real program (RGT, TITAN, NGTT). The graphic should be
  captioned as a notional concept, the same way
  `docs/OPERATIONAL_CONTEXT.md` cites those programs as evidence the
  direction is real without claiming to depict them.
- A single mission thread. If the graphic shows a product flowing through
  the pipeline, it should either show multiple tiers moving in parallel
  (reflecting `docs/ALLOCATION_SPACE.md`'s tiered-delivery axis) or be
  explicitly captioned as one specific thread's path, not implied to be
  the only one.

## Annotations the graphic should carry

- A label on the space-to-edge link indicating it's contact-windowed, not
  continuous (the single biggest driver of `docs/TRADE_STUDY.md`'s
  results).
- A dashed or otherwise visually distinct line for the direct-edge tasking
  path versus the reachback path, since `docs/ACQUISITION_IMPLICATIONS.md`
  recommends both be available.
- A caption stating the notional/unofficial disclaimer, matching the
  header block used in `LEO_EDGE_OPERATIONAL_VIEWPOINTS.md`.

## Status

Not produced in this pass. `README.md` and
`LEO_EDGE_OPERATIONAL_VIEWPOINTS.md` should stop referencing the old
`docs/figures/ov1_concept.png` as the current concept graphic once this
spec is available to act on; see `docs/DECISION_LOG.md` for how that
retirement is tracked.
