# Engineering status

The [model catalogs](../model/) hold the project's conceptual architecture: needs, requirements, functions, elements, alternatives, interfaces, measures, and verification links. The validator and generator check that the [GitHub views](reference/VIEWS.md) reflect those definitions.

| Area | Status |
|---|---|
| Architecture and traceability | Cataloged and generated; validation checks identifiers, links, and candidate allocations. |
| Product and contact logic | Tested for sufficiency, terminal derivation, same pass contact, capacity, and byte carryover. |
| Selected comparison | [Current evidence](../results/current/) records configuration, paired cases, audit, and source hashes. |
| Manuscript | [Draft](../paper/manuscript_draft.md) follows one trace from need to verification and discusses bounded synthetic cases. |
| Product utility | Assumed; no user evaluation or real image quality validation. |
| Tasking and interface | Conceptual fields are defined, but real message exchange and interoperability remain open. |
| Physical feasibility | Synthetic access and generic terminal assumptions; no real service availability claim. |

The [trade study](TRADE_STUDY.md) uses selected cases to show where access prevents every candidate from meeting a deadline and where product order changes modeled delivery. The cases do not identify one candidate for every condition. The [submitted abstract](../paper/submitted_abstract.md) remains unchanged. Before external submission, the draft needs author review, a substantive literature review, and evidence about product quality and user value.
