# Figures

Every figure here is generated by a script in `figures/scripts/` and is reproducible with `make figures` (or by running a single script directly with `PYTHONPATH=src`). None of the numbers are invented; each script either reads a frozen CSV in `results/frozen/v3/` or computes directly from the real simulation code in `src/leo_edge/`.

| Figure | Script | What it shows | Data source |
|---|---|---|---|
| `fig01.png` | `fig01_system_architecture.py` | Block diagram of the satellite-to-edge system: sensor, onboard processor, downlink, ground terminal, edge server, cloud archive. | Static diagram, no data. |
| `fig02.png` | `fig02_sensitivity_tornado.py` | How much time to first useful product (TFUP) changes when processor power, contact margin, or compression ratio move 20% off baseline. | Closed-form TFUP model in the script itself. |
| `fig03.png` | `fig03_progressive_timeline.py` | When each product tier (metadata, thumbnail, quicklook, ROI, full) becomes available for the Progressive architecture. | Deterministic per-tier timing model. |
| `fig04.png` | `fig04_regime_heatmap.py` | Single-contact-window result: which architecture finishes fastest (lowest time to complete product) across a grid of downlink rates and contact durations, with cells honestly marked "no completion" where nothing finished. This is single-window evidence, not the headline result; see `figures/fig20.png` and `docs/MODEL_REFERENCE.md`. | Computed directly from `leo_edge.simulation.run_static_architecture`, cached to `results/frozen/v3/fig04_data.csv`. |
| `fig05.png` | `fig05_pareto_frontier.py` | Processing energy vs. TFUP trade-off across architectures, with the Pareto-optimal points marked. | `results/frozen/v3/e03_results.csv`. |
| `fig06.png` | `fig06_contact_distribution.py` | Distribution of real contact window durations over a one-week pass schedule. | `results/frozen/v3/e01_access_windows.csv`. |
| `fig19.png` | `fig19_access_sweep_by_thread.py` | Mission-thread success rate vs. satellite count, one panel per mission thread, Wilson 95% CI bands, single-terminal slice. | `results/frozen/v3/e12_access_sweep.csv`. |
| `fig20.png` | `fig20_access_heatmap.py` | **The headline result.** Best statistically-distinguishable architecture over satellites x terminals (paired bootstrap significance test); cells with no significant winner are labeled that way, not given an arbitrary pick. | `results/frozen/v3/e12_best_architecture_by_access.csv`. |
| `fig21.png` | `fig21_cost_tradeoff.py` | Notional cost-vs-success-rate tradeoff curve. Every cost number is an explicitly labeled ASSUMED relative unit, not a real acquisition estimate. | `results/frozen/v3/e12_cost_tradeoff.csv`. |
| `infographic_summary.pdf` | `fig_infographic_pdf.py` | One-page summary combining the system diagram, the single-window regime map, and a table of median metrics per architecture. | `results/frozen/v3/e03_results.csv`, `fig01.png`, `fig04.png`. |
| `fig15_constellation_coverage.png` | `experiments/e09_constellation_handoff.py` | Continuous ground-contact coverage for one satellite versus a 3-satellite constellation over 24 hours. | Generated inline as part of running the e09 experiment, not a separate `figures/scripts/` script. |
| `fig16_storage_health.png` | `experiments/e10_storage_wear.py` | Flash storage health over a 30-day mission as write amplification accumulates wear. | Generated inline as part of running the e10 experiment. |
| `monte_carlo_distribution.png` | `scripts/monte_carlo_uncertainty.py` (top-level `scripts/`, not `figures/scripts/`) | Spread of outcomes under contact-capacity uncertainty. | `results/frozen/v3/monte_carlo.csv`. |

`scripts/import_hardware_benchmark.py` can additionally produce `fig17_measured_vs_modeled.png` (measured vs. modeled processing time) from a real hardware benchmark CSV, but it also rewrites `src/leo_edge/imagery/benchmark.py`'s measured-timing constants as a side effect, so it isn't run as part of the standard `make experiments` / `make figures` pipeline. Run it manually only when re-calibrating against a new hardware benchmark.

`fig02_data.csv`/`fig03_data.csv`/`fig04_data.csv` are self-caching: each script writes its own computed grid to `results/frozen/v3/` on first run and reads it back on subsequent runs, rather than being produced by a separate experiment script.
